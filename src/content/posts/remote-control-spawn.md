## やったこと

Claude Codeのリモートコントロールで `--spawn` フラグを使って、1つのサーバープロセスから複数のセッションを同時に立ち上げられるようにした。

## なぜやったか

前回の記事でリモートコントロールの基本的なワークフローを書いたが、通常のリモートコントロールだと1プロセスにつき1セッションしか持てない。複数の作業を並行して進めたいとき、たとえばブログ記事のレビューをしながら別のリポジトリでコード修正を指示するようなケースでは、いちいち別のターミナルで `claude remote-control` を立ち上げる必要があった。`--spawn` を使えば、1つのサーバープロセスで複数セッションをまとめて管理できる。

## どうやったか

サーバーモードで `--spawn` フラグを付けて起動する。

```bash
claude remote-control --spawn same-dir
```

`--spawn` には2つのモードがある。

- **same-dir**（デフォルト）: すべてのセッションが同じ作業ディレクトリを共有する。同じファイルを同時に編集すると競合する可能性がある
- **worktree**: セッションごとにgit worktreeが作られ、それぞれ独立したディレクトリで作業する。gitリポジトリが必要

worktreeモードで起動する場合はこう書く。

```bash
claude remote-control --spawn worktree --capacity 4
```

`--capacity` で同時セッション数の上限を指定できる。デフォルトは32。起動中に `w` キーを押すとspawnモードをsame-dirとworktreeの間で切り替えられる。

claude.ai/codeやClaudeアプリから接続すると、サーバーが自動的に新しいセッションを生成してくれる。各セッションは独立して動くので、スマホからそれぞれ別の指示を出せる。

## 感想

worktreeモードが特に便利だと感じた。同じリポジトリで複数の作業ブランチを並行して進められるので、ファイルの競合を気にしなくていい。たとえばブログ記事の修正と新機能の開発を同時に走らせるような使い方ができる。1プロセスでまとめて管理できるのも地味にありがたい。ターミナルのタブが増えすぎない。
